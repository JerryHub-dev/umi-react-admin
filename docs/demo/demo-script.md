# 主线演示手册（E01–E10，目标约 12 分钟）

一条从「告警发生」到「验收归档、报表留痕」的完整主线，覆盖台账 D03 的可核对变化与 F02–F09 的修复点。配套文档：[role-matrix.md](role-matrix.md)（角色与权限）、[demo-scenarios.json](demo-scenarios.json)（机器可读场景清单，含稳定对象 ID）。

## 前置条件

- `pnpm install && pnpm start`（端口 8000），演示模式需 `UMI_APP_DEMO_MODE=true`（见 `.env.example`；未开启时登录页没有快捷体验按钮，也没有场景菜单）。
- 浏览器建议桌面宽度 ≥ 1280；需联网（OpenLayers 页的 OSM 瓦片、视频页的演示 mp4 走 CDN）。高德页需要 `AMAP_KEY`，Cesium 页无 `CESIUM_ION_TOKEN` 时自动回落 OSM 底图——主线只用 OpenLayers，无凭据要求。
- 演讲者全程使用 `admin` 账号（除 E09 外）。固定场景的对象 ID（`SCENARIO_IDS`，见 [src/demo/scenarios.ts](../../src/demo/scenarios.ts)）跨日、跨语言、跨重置稳定，可直接念出来定位。

## 基线读数（进入场景后、动手前先抄下来）

五个数全部从界面现场读取，不要背数字（自然分布的基数随演示日变化）：

| 记号  | 含义         | 在哪里读                                                                      |
| ----- | ------------ | ----------------------------------------------------------------------------- |
| **O** | 在线设备数   | 工作台 KPI「在线设备」（显示为 `x / 243 台`，243 = 自然分布 240 + 场景 3 台） |
| **U** | 未恢复告警数 | 告警中心打开「只看未恢复」开关后表格分页的总数                                |
| **N** | 今日告警数   | 工作台 KPI「今日告警」                                                        |
| **V** | 用户总数     | 用户管理页分页总数（初始 86）                                                 |
| **T** | 工单看板总数 | 工单看板「全部」筛选下三列计数之和（新工单始终在窗口内，差值可观测）          |

## E01 管理员登录并进入固定演示场景（约 1 分钟）

- **预算时长**：1 分钟。
- **起点**：`/login`。
- **精确操作**：点击主按钮「以管理员体验」（或表单输入 `admin` / `demo` 后登录）→ 点击右上角头像打开账户菜单 → 点「进入固定演示场景」→ 确认弹窗「确定」。
- **语义对象 ID**：无（本步是模式切换）。
- **预期可见结果**：整页自动刷新；顶栏右侧出现金色「演示时间 MM-DD HH:mm」标签（悬停可见完整说明：时钟冻结、数据不随现实时间推进）。此时时钟冻结、演示补丁清空，场景初始数据就位。菜单里「进入固定演示场景」变为「退出受控场景」。
- **下一步**：等工作台加载完成，进入 E02。若标签未出现，说明当前不是受控模式或账号无 `system.demo.reset` 权限（场景菜单仅对管理员可见）。

## E02 工作台基线读数（约 1 分钟）

- **预算时长**：1 分钟。
- **起点**：`/dashboard`。
- **精确操作**：抄下 KPI「在线设备」（O）与「今日告警」（N）；点击「在线设备」卡片跳转 `/ops/devices` 再返回；点击「今日告警」卡片跳转 `/ops/alarms`，打开「只看未恢复」开关抄下 U，返回工作台。顺带到 `/ops/tickets` 抄三列计数之和（T）、`/system/users` 抄用户总数（V）。
- **语义对象 ID**：无。
- **预期可见结果**：两张 KPI 卡都是链接，点进去后的列表口径与指标一致（在线设备 ↔ 设备台账状态筛选；今日告警 ↔ 告警中心当日筛选）。KPI 右上角有「数据更新于 HH:mm:ss」的手动刷新按钮，页面每 60 秒也会自动刷新（受控模式下数值稳定不动）。
- **下一步**：回 `/ops/devices`，进入 E03。

## E03 设备详情与地图定位（约 1.5 分钟）

- **预算时长**：1.5 分钟。
- **起点**：`/ops/devices`。
- **精确操作**：在搜索框输入关键字「演示」并查询 → 点击设备「演示 · 主线故障站」（`DEV-SCN-01`）打开详情抽屉 → 点抽屉里的「在地图中定位」按钮 → 在地图页看完弹窗后用浏览器返回键回到设备抽屉。
- **语义对象 ID**：`DEV-SCN-01`。
- **预期可见结果**：
  - 搜索命中 3 台演示设备（`DEV-SCN-01/02/03`）；
  - 抽屉显示状态「离线」，最近告警列表第一条为 `ALM-SCN-MAIN`（严重 · 设备离线 · 未恢复），告警条目本身是链接，可跳转告警中心并自动带出关键字筛选；
  - 「在地图中定位」跳转 `/map/openlayers?focus=DEV-SCN-01`：视图飞到北京（缩放 9 级）并直接弹出该站点卡片（名称、`DEV-SCN-01`、离线状态、位置 / 型号 / 在线率 / 心跳）——深链接由 [src/pages/Map/OpenLayers/index.tsx](../../src/pages/Map/OpenLayers/index.tsx) 处理，无需手工缩放找点。此页需要网络加载 OSM 瓦片。
- **下一步**：返回后进入告警中心，E04。

## E04 主线告警转工单 + 深链接直达（约 1 分钟）

- **预算时长**：1 分钟。
- **起点**：`/ops/alarms`。
- **精确操作**：保持「只看未恢复」开启，关键字输入 `ALM-SCN-MAIN`（或「演示」）查询 → 在该行「操作」列点「处置 ▾」下拉 → 选「转工单」→ 刷新后点击该行状态列下方出现的工单号链接 `WO-SCN-MAIN`。
- **语义对象 ID**：`ALM-SCN-MAIN` → 新建 `WO-SCN-MAIN`。
- **预期可见结果**：
  - 告警状态变为「已转工单」，状态列出现 `WO-SCN-MAIN` 深链接；
  - 点击后跳转 `/ops/tickets?focus=WO-SCN-MAIN` 并**直接打开工单详情抽屉**（新工单不在初始看板数据里时，页面按 ID 独立加载，无需刷新）；
  - 工单为 P1 故障处理、状态「待处理」，SLA 4 小时；
  - 此时**设备仍是离线**（转单 ≠ 恢复，见 [src/demo/availability.ts](../../src/demo/availability.ts)）：O、U 均未变，只有 T+1。
- **下一步**：保持抽屉打开，E05。

## E05 派工 → 处理 → 完成 → 签名验收（约 2 分钟）

- **预算时长**：2 分钟。
- **起点**：`/ops/tickets`（`WO-SCN-MAIN` 详情抽屉打开）。
- **精确操作**：
  1. 抽屉下半部「处理人」下拉中任选一位可派工人员（在职的值班长 / 运维工程师，支持按姓名搜索）；
  2. 底部「流转到」分段控件依次点「处理中」→「已完成」；
  3. 打开 `/components/signature`，在「待验收工单」下拉确认选中 `WO-SCN-MAIN`（默认自动选中第一张候选）→ 在签名区签字 → 点「确认验收」→ 在成功页点「继续验收下一单」。
- **语义对象 ID**：`WO-SCN-MAIN`（签名写回其 `acceptance` 字段）。
- **预期可见结果**：
  - 改派成功提示「已改派 WO-SCN-MAIN 的处理人」；每次流转有「工单 … 已移至『处理中 / 已完成』」提示；
  - 详情「处理进度」步骤条推进：创建 → 开始处理 → 完成 → 验收签字（含签字人与时间）；
  - 签名页提交后显示成功结果页：签名图（白底黑字）、「下载签名 PNG」与「继续验收下一单」按钮；点击继续后画板清空并自动选中下一张待验收工单（场景里还有 `WO-SCN-ACC-1` / `WO-SCN-ACC-2` 两张独立候选）；
  - 完成那一刻关联告警 `ALM-SCN-MAIN` 写入恢复时间（`recoveredAt`），设备状态由派生规则回到在线。
- **下一步**：回工作台核对数字，E06。

## E06 核对联动：O+1 / U−1（约 0.5 分钟）

- **预算时长**：0.5 分钟。
- **起点**：`/dashboard`。
- **精确操作**：点手动刷新按钮（或等 60 秒自动刷新）核对 KPI；再到 `/ops/devices` 搜「演示」确认 `DEV-SCN-01` 状态；最后到 `/ops/alarms` 开「只看未恢复」核对总数。
- **语义对象 ID**：`DEV-SCN-01`。
- **预期可见结果**：在线设备 **O+1**（243 台中在线数加一）、未恢复告警 **U−1**、今日告警 **N 不变**（处置不改变发生时间，受控模式下时钟冻结）；`DEV-SCN-01` 在台账与地图上都显示「在线」，心跳时间更新为演示当前时间。
- **下一步**：进入文档模块，E07。

## E07 PDF 月报与页面截图（约 1.5 分钟）

- **预算时长**：1.5 分钟。
- **起点**：`/document/pdf`。
- **精确操作**：进入页面后等待自动生成（约 1–2 秒）→ 预览滚动确认两页内容 → 点「下载 PDF」；再打开 `/components/screenshot` → 点「截图预览」看弹窗 → 关闭 → 点「下载 PNG」。
- **语义对象 ID**：PDF 报表聚合的是当前全部数据；截图卡片取「最近一条严重告警」及其设备——受控场景下通常是演示告警之一，以卡片上实际显示的告警编号为准核对。
- **预期可见结果**：
  - PDF 为 2 页「监测运营月报」，KPI、告警 Top 设备与当前页面一致（同一份 `dashboard/overview` 数据派生），文件名 `monthly-report.pdf`；
  - 截图弹窗内容与页面虚线框内一致（含暗色主题背景），下载文件名为 `<告警编号>.png`；
  - 两页均可说明「报表与页面指标同源」：刚做完的 O+1 已体现在月报的在线数里。
- **下一步**：E08。

  4. 打开 `/system/users`，关键字输入 `demo.` 查询。
- **语义对象 ID**：新用户 `demo.iris` / `demo.hugo` / `demo.nora`。
- **预期可见结果**：

## 基线核对表

E02 抄基线，E04–E08 做操作，按下表核对（依据 [src/demo/availability.ts](../../src/demo/availability.ts) 的恢复语义与 [src/demo/server/routes.ts](../../src/demo/server/routes.ts) 的写路径）：

| 记号 | 指标 | 基线（E02） | E04 转工单后 | E05 完成 + 验收后 | E08 导入后 | 说明 |
| --- | --- | --- | --- | --- | --- | --- |
| O | 在线设备 | 记录值 | 不变（转单 ≠ 恢复） | **+1** | 不变 | 完成时告警写恢复时间，`DEV-SCN-01` 派生回在线 |
| U | 未恢复告警 | 记录值 | 不变 | **−1** | 不变 | 「已转工单但未恢复」在完成前仍在未恢复池（F08 口径） |
| N | 今日告警 | 记录值 | 不变 | 不变 | 不变 | 处置不改变 `occurredAt`，且时钟冻结 |
| V | 用户总数 | 86 | 不变 | 不变 | **+3**（→ 89） | `demo.iris` / `demo.hugo` / `demo.nora` |
| T | 工单看板总数 | 记录值 | **+1** | 维持 +1（仍在窗口内） | 不变 | 新工单 `WO-SCN-MAIN` 从待处理走到已完成 |

验收签字本身不改任何计数（只写 `acceptance` 字段）；E10 重置后五行全部回到基线。

## 重置与再演示

- **连续两轮受支持**：受控模式下「重置演示数据」= 清空补丁 + 时钟重新锚定到当前时刻（[src/demo/server/routes.ts](../../src/demo/server/routes.ts) 的 `/api/v1/demo/reset`），场景记录相对新锚点完整重建。第一轮演完直接重置即可开第二轮，不需要退出场景或换浏览器。
- **两轮之间**的差异只有「演示时间」标签的锚点前进；所有 `SCN` 对象的 ID、状态、时间关系保持设计约束（创建 ≤ 响应 ≤ 完成 ≤ 验收）。
- **彻底退出受控模式**：头像菜单「退出受控场景」→ 回实时时钟 + 清空补丁（自然分布数据随真实时间推进，长开页面跨过 60 秒阈值会按当前时间重建基础数据、补丁保留，见 [src/demo/clock.ts](../../src/demo/clock.ts) 与 [src/demo/store.ts](../../src/demo/store.ts)）。
- **多标签页**：演示时钟与补丁经 storage 事件互通；另一标签页进入 / 退出场景或重置后，本标签页在下次请求或刷新时同步。
- 排查：若「进入固定演示场景」菜单不存在，确认演示模式开启且当前账号是 admin；若 Cesium 底图空白或出现「底图瓦片加载失败」：无 token 时链路是「夜航滤镜」OSM →（探针通过）carto 暗色 →（OSM 不可达）高德兜底，三者都不可达才告警，检查网络或 CSP 部署副本（需放行 tile.openstreetmap.org、_.basemaps.cartocdn.com、_.autonavi.com）；OpenLayers 页只用 OSM。

## 附录：外部条件依赖与未验证边界（如实声明）

1. **高德地图合法 Key 分支**：验证的是「缺 Key 兜底」（默认入口切 OpenLayers、高德页错误提示+跳转+禁用无效控件）。配置合法 Key 后的高德功能未在浏览器实测，不声称通过。
